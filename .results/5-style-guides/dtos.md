# Style Guide: DTOs (Data Transfer Objects)

## Unique Conventions for SalahPlanner DTOs

### 1. Namespace Structure

DTOs are organized by feature domain:

```
PrayerTasker.Application/
└── DTOs/
    ├── Account/
    │   ├── LoginDto.cs
    │   ├── LoginResponseDto.cs
    │   ├── RegisterDto.cs
    │   ├── RegisterResponseDto.cs
    │   └── UserSettingsDto.cs
    ├── Task/
    │   ├── CreateTaskDto.cs
    │   ├── TaskDto.cs
    │   └── UpdateTaskDto.cs
    └── PrayerTime/
        └── PrayerTimesDto.cs
```

### 2. Required Property Pattern

Use `required` keyword for mandatory properties:

**✅ Correct Pattern:**
```csharp
namespace PrayerTasker.Application.DTOs.Task;

public class CreateTaskDto
{
    [Required, MaxLength(100)]
    public required string Title { get; set; }

    [MaxLength(500)]
    public string? Description { get; set; }  // Optional - nullable

    public DateTime? TaskDate { get; set; }   // Optional - nullable

    [Required]
    public PrayerTimeSlot Slot { get; set; }  // Required - non-nullable enum
}
```

**❌ Avoid:**
```csharp
// Don't omit 'required' keyword for mandatory string properties
public string Title { get; set; }  // Compiler warning

// Don't use nullable for required properties
public string? Title { get; set; }
```

### 3. Data Annotations

Use Data Annotations for validation:

```csharp
public class RegisterDto
{
    [Required]
    public required string UserName { get; set; }

    [Required, EmailAddress]
    public required string Email { get; set; }

    [Required]
    public required string FullName { get; set; }

    [Required, MinLength(6)]
    public required string Password { get; set; }
}
```

**Common Annotations:**
- `[Required]` - Property must have a value
- `[EmailAddress]` - Validates email format
- `[MinLength(n)]` - Minimum string length
- `[MaxLength(n)]` - Maximum string length
- `[Range(min, max)]` - Numeric range validation

### 4. Response DTO Pattern

Response DTOs include result data and status messages:

```csharp
public class LoginResponseDto
{
    public string UserId { get; set; } = string.Empty;
    public string UserName { get; set; } = string.Empty;
    public string Email { get; set; } = string.Empty;
    public string FullName { get; set; } = string.Empty;
    public string Token { get; set; } = string.Empty;
    public DateTime Expiration { get; set; }
    public string Message { get; set; } = string.Empty;
}

public class RegisterResponseDto
{
    public string UserId { get; set; } = string.Empty;
    public string UserName { get; set; } = string.Empty;
    public string Email { get; set; } = string.Empty;
    public string Message { get; set; } = string.Empty;
}
```

**Pattern:**
- Include core data (UserId, UserName, Email, etc.)
- Include JWT token (for auth responses)
- Include expiration (for token-based responses)
- Include human-readable Message field

### 5. Create vs Update DTOs

Separate DTOs for create and update operations:

**CreateTaskDto** (for POST requests):
```csharp
public class CreateTaskDto
{
    [Required, MaxLength(100)]
    public required string Title { get; set; }

    [MaxLength(500)]
    public string? Description { get; set; }

    public DateTime? TaskDate { get; set; }

    [Required]
    public PrayerTimeSlot Slot { get; set; }

    // No Id property - generated by backend
    // No ApplicationUserId - extracted from JWT
    // No CreatedAt - set by backend
}
```

**UpdateTaskDto** (for PUT requests):
```csharp
public class UpdateTaskDto
{
    [Required, MaxLength(100)]
    public required string Title { get; set; }

    [MaxLength(500)]
    public string? Description { get; set; }

    public DateTime? TaskDate { get; set; }

    [Required]
    public PrayerTimeSlot Slot { get; set; }

    // No Id - passed in URL parameter
    // No server-managed fields
}
```

**TaskDto** (for GET responses):
```csharp
public class TaskDto
{
    public Guid Id { get; set; }

    [Required, MaxLength(100)]
    public required string Title { get; set; }

    [MaxLength(500)]
    public string? Description { get; set; }

    public DateTime CreatedAt { get; set; }
    public DateTime? TaskDate { get; set; }
    public bool IsCompleted { get; set; }

    [Required]
    public PrayerTimeSlot Slot { get; set; }

    // Includes all fields for read operations
}
```

### 6. Nullable Reference Types

Enable nullable reference types and use `?` appropriately:

```csharp
public class UserSettingsDto
{
    [Required]
    public required string DefaultCity { get; set; }      // Required, non-nullable

    [Required]
    public required string DefaultCountry { get; set; }   // Required, non-nullable

    [Required]
    public required string CalculationMethod { get; set; } // Required, non-nullable

    public string? PreferredLanguage { get; set; }         // Optional, nullable
}
```

**Rules:**
- Required properties: Use `required` keyword, no `?`
- Optional properties: Use `?` for nullability
- Enable `<Nullable>enable</Nullable>` in project file

### 7. Default Values

Provide default values for non-nullable properties:

```csharp
public class LoginResponseDto
{
    public string UserId { get; set; } = string.Empty;
    public string UserName { get; set; } = string.Empty;
    public string Email { get; set; } = string.Empty;
    public string FullName { get; set; } = string.Empty;
    public string Token { get; set; } = string.Empty;
    public DateTime Expiration { get; set; } = DateTime.MinValue;
    public string Message { get; set; } = string.Empty;
}
```

### 8. Enum Properties

Use enum types directly (no conversion to strings):

```csharp
public class CreateTaskDto
{
    [Required]
    public PrayerTimeSlot Slot { get; set; }  // Enum, not string
}

// Enum definition (in Domain layer)
public enum PrayerTimeSlot
{
    Fajr = 0,
    Dhuhr = 1,
    Asr = 2,
    Maghrib = 3,
    Isha = 4
}
```

API receives/sends enum as integer or string based on configuration.

### 9. DateTime Properties

Use `DateTime` type for date/time fields:

```csharp
public class TaskDto
{
    public DateTime CreatedAt { get; set; }        // Non-nullable - always set
    public DateTime? TaskDate { get; set; }        // Nullable - optional
}

public class PrayerTimesDto
{
    public DateTime Date { get; set; }             // Non-nullable
    public string Fajr { get; set; }               // Time as string (HH:mm format)
    public string Sunrise { get; set; }
    public string Dhuhr { get; set; }
    public string Asr { get; set; }
    public string Maghrib { get; set; }
    public string Isha { get; set; }
}
```

**Pattern:**
- Use `DateTime` for full date-time values
- Use `string` for time-only values (e.g., "14:30")
- Use `DateTime?` for optional dates

### 10. GUID vs String IDs

Use `Guid` type for entity IDs in response DTOs, `string` in some contexts:

```csharp
public class TaskDto
{
    public Guid Id { get; set; }  // Guid type
}

public class LoginResponseDto
{
    public string UserId { get; set; }  // String representation of Guid
}
```

**Pattern:**
- Task/entity DTOs: Use `Guid`
- Auth responses: Use `string` for flexibility

### 11. No Navigation Properties

DTOs should NOT include navigation properties:

**✅ Correct:**
```csharp
public class TaskDto
{
    public Guid Id { get; set; }
    public required string Title { get; set; }
    public PrayerTimeSlot Slot { get; set; }
    // No ApplicationUser property
}
```

**❌ Avoid:**
```csharp
public class TaskDto
{
    public Guid Id { get; set; }
    public required string Title { get; set; }
    public ApplicationUser ApplicationUser { get; set; }  // ❌ Don't expose entities
}
```

### 12. Mapping with AutoMapper

DTOs are mapped to/from entities using AutoMapper:

```csharp
// MappingProfile.cs
public class MappingProfile : Profile
{
    public MappingProfile()
    {
        CreateMap<CreateTaskDto, Taask>();
        CreateMap<Taask, TaskDto>();
        CreateMap<UpdateTaskDto, Taask>();
        CreateMap<RegisterDto, ApplicationUser>();
    }
}

// Usage in service
var task = _mapper.Map<Taask>(dto);
var taskDto = _mapper.Map<TaskDto>(task);
```

### 13. Avoid Circular References

DTOs must be serializable without circular references:

**✅ Correct:**
```csharp
public class TaskDto
{
    public Guid Id { get; set; }
    public required string Title { get; set; }
    // Flat structure
}
```

**❌ Avoid:**
```csharp
public class TaskDto
{
    public Guid Id { get; set; }
    public UserDto User { get; set; }
}

public class UserDto
{
    public Guid Id { get; set; }
    public List<TaskDto> Tasks { get; set; }  // ❌ Circular reference
}
```

### 14. Consistent Naming

DTO classes follow naming pattern:

- **Create**: `CreateXxxDto` (e.g., `CreateTaskDto`)
- **Update**: `UpdateXxxDto` (e.g., `UpdateTaskDto`)
- **Response**: `XxxDto` or `XxxResponseDto` (e.g., `TaskDto`, `LoginResponseDto`)
- **Settings/Config**: `XxxSettingsDto` (e.g., `UserSettingsDto`)

### 15. Frontend TypeScript Models

Frontend mirrors DTO structure:

**Backend DTO (C#):**
```csharp
public class TaskDto
{
    public Guid Id { get; set; }
    public required string Title { get; set; }
    public string? Description { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? TaskDate { get; set; }
    public bool IsCompleted { get; set; }
    public PrayerTimeSlot Slot { get; set; }
}
```

**Frontend Model (TypeScript):**
```typescript
export interface Task {
  id: string;
  title: string;
  description?: string;
  createdAt: Date;
  taskDate?: Date;
  isCompleted: boolean;
  slot: PrayerTimeSlot;
}
```

**Differences:**
- `Guid` → `string`
- `DateTime` → `Date`
- `required` → not used in TypeScript interfaces
- `?` (nullable) → `?` (optional)

## Summary of Key Patterns

1. Organize DTOs by feature domain (Account/, Task/, PrayerTime/)
2. Use `required` keyword for mandatory string properties
3. Apply Data Annotations for validation
4. Separate Create, Update, and Response DTOs
5. Use nullable reference types (`?`) for optional fields
6. Use enums directly (not strings)
7. Use `DateTime` for dates, `string` for times
8. No navigation properties or circular references
9. Provide default values for non-nullable properties
10. Mirror DTO structure in frontend TypeScript models
11. Use AutoMapper for entity ↔ DTO conversions
12. Include Message field in response DTOs
